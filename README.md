## Модель

Занятия представлены четырьмя видами классов, т.к. они отличаются данными. Все классы реализуют Session, содержащий общие свойства даты и темы. Интерфейс объявлен sealed для проверки полноты обработки типов в when при компиляции.

Выбраны обычные классы, т.к. data class не предусматривает глубокое копирование вложенных коллекций.

Чтобы неправильные занятия, минуя парсер, нельзя было создать, проверки были объявлены в блоке init, который выполняется при каждом вызове конструктора. При нарушении require выбрасывает IllegalArgumentException с пояснением.

Объявления `val teachers: List<String>` недостаточно для защиты преподавателей (можно, не изменяя ссылку на контейнер, изменять объекты внутри него), поэтому мы используем List.copyOf, чтобы защитить содержимое от изменений. По той же логике в методе реестра `all()` использует `List.copyOf`.

AuditedSessionRepository использует SessionRepository by delegate, чтобы передать реализацию методов интерфейса внутреннему реестру. Метод all() прямо не реализован - и делегируется автоматически. 

## Делегирование

Переопределить только add в журнале (`AuditedSessionRepository`) и делегировать эту функцию на внутренний реестр (`InMemorySessionRepository`) недостаточно, т.к. в таком случае вызовется метод add именно родительский, а не переопределенный add класса-обертки, поэтому журнал не пополнится.

## Проверка «сломай свою модель»

| Попытка | Что защищает |
|---|---|
| Пустая тема | `require` с проверкой `isNotBlank()` в конструкторе |
| Год `0` или `10000` | `require` с диапазоном `1..9999` |
| Действующее занятие без преподавателей | Проверка размера списка |
| Сдача с одним преподавателем | Проверка `size >= 2` |
| Два одинаковых преподавателя | Сравнение размера списка с размером множества |
| Изменение исходного списка | Независимая копия через `List.copyOf` |
| Изменение выданного списка | Список запрещает изменение: `UnsupportedOperationException` |
| Обход через `copy()` | У занятий `copy()` нет |

### Дополнительные сообщения ошибок

Для доменных отказов используется формат `DESCRIPTION in "FIELD": "VALUE"`:

| Нарушение | DESCRIPTION |
|---|---|
| Управляющие символы | `control characters` |
| Окружающие пробельные символы | `surrounding whitespace` |
| Неверные поля отмены | `invalid cancelled field` |
| Недопустимое место | `invalid location` |
| Недопустимый преподаватель | `invalid teacher` |
| Повтор преподавателя | `duplicate teacher` |
